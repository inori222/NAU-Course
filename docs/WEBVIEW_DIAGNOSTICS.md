# WebView 白屏排查

用户在 Android 16 上观察到学生页面 `body` 高度为零；手动执行布局高度修复后反馈能够查看和导入课表。应用已加入条件受限的自动修复，自动触发版仍需更多设备验证；零高度的根本成因尚未确认。诊断入口仅存在于 Debug 变体，事件仅保存在本次页面的内存中；关闭页面后丢失。Release 变体不显示入口，也不记录事件。

1. 安装本次构建的 Debug APK，在应用中打开教务系统，自行完成统一认证，复现白屏；可尝试一次重新加载。
2. 点击“查看调试诊断”，选择“复制诊断”，把复制出的内容发给开发者。也请提供手机 Android 版本和系统 Android System WebView 版本。请勿发送账号、密码、Cookie、认证票据、课表、网页源码或完整 URL。
3. 记录只显示协议和两个已确认的学校主机，其他学校子域名统一显示为“其他南审主机”；路径、端口、用户信息、查询参数、片段和控制台原文不会记录。若诊断指向其他学校主机，需要另行核对该资源对应的**公开主机名和用途**，不要提供其 URL 路径和参数。
4. 应用会在页面加载后短暂等待，只在学校已观察的页面结构、EasyUI 已初始化且 body 高度至多 1 像素等条件满足时，临时将 body 高度设为视口高度并调用 EasyUI 的 resize 方法；页面根元素高度异常时也会临时调整。Debug 版可点击“尝试恢复布局”手动调用相同检查。此兼容逻辑会改变符合条件页面的布局，重新加载可撤销，不会修改登录凭据或网络安全策略。

诊断记录 WebView 可观察到的主页面开始、完成、历史和导航事件；HTTP 资源请求（不代表请求已成功）、网络错误、HTTP 4xx/5xx、证书错误、渲染进程退出及固定类别的控制台错误/混合内容警告。点击诊断时还采集 WebView 尺寸、可见性和硬件加速状态，以及页面和样本中 `FrameContent` iframe 的元素数量、尺寸、可见状态、文档就绪状态与是否同源可读取；不会读取页面文字、HTML 或任何 URL 路径。结构检查仅代表点击时的瞬间状态，且元素自身可见不保证其未被覆盖或所有祖先元素可见。

子资源和 iframe 的错误共用一类，回调本身不提供可靠区分；部分被浏览器阻止的请求或跳转可能没有回调。最后一条主页面完成/历史记录只是可观察到的地址来源，不能保证网页随后没有执行脚本或所有资源都已经加载。敏感信息不会从 console 原文、错误描述或 URL 路径提取出来，因此诊断可能无法确定具体脚本及失败资源。

目前仅主页面为 HTTP 时显示明文警告；HTTPS 主页面中出现的 HTTP 子资源可在 Debug 诊断中观察，但不会据此推断其一定成功或被拦截。应用没有放宽混合内容策略、没有忽略证书错误，也没有增加任何明文域名。HTTP 连接可能泄露或被篡改，使用可信网络也不能完全消除风险。
